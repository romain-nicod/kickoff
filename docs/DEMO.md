# Demo

Target: **the audience sees the product answer its own question in under
thirty seconds.** Everything else is commentary.

## The scenario

One device, one screen mirrored, one person driving, one speaking.
Rehearsed out loud the day before, timed.

| # | What happens | What is said | Time |
|---|---|---|---|
| 1 | The problem | | 25 s |
| 2 | The first screen | <!-- say nothing, let it land --> | 5 s |
| 3 | The differentiator | | 20 s |
| 4 | The main gesture | | 10 s |
| 5 | The payoff | | 15 s |
| 6 | The variation that proves the point | | 20 s |
| 7 | What we did not build, and why | | 20 s |

Two minutes of product. Keep the rest for questions.

**Step 7 is not an apology.** Naming the heaviest thing you skipped, and
what you replaced it with, is what makes the rest credible.

## Rules

**Nobody reads the screen out loud.** The audience can read.

**Hypotheses are named as hypotheses.** Every assumed number is
presented as assumed. It is the one thing that can cost the audience's
trust in a single sentence.

**One person drives, one person speaks.** Two hands on one device is a
demo that fumbles.

## Plan B

| If | Then |
|---|---|
| No network | A screen recording of the same scenario, recorded during the rehearsal |
| A permission is refused on stage | Show it as a feature: the fallback path exists — rehearse it too |
| A third-party API is down | Stop before it, describe the rest |
| The device dies | Second device, charged, app already installed |

The recording and the second device are the QA & demo owner's
responsibility, checked the day before.
