# Boilerplate — `minimal`, Le Wagon's Rails template

**The default, and you need a reason not to use it.** The application
skeleton is generated by **`minimal`** — the template of that exact name
in [`lewagon/rails-templates`](https://github.com/lewagon/rails-templates),
the one taught at the bootcamp. Its sibling `devise.rb` adds user
accounts; `minimal.rb` is the base, and the base is what we start from.

It is a **generator run at creation time**, not a skeleton frozen inside
this repository — which is why it never rots between framework releases.

Why this one rather than a bare `rails new`: it is the base the team
learnt on. The asset pipeline, the stylesheet architecture, the form
helpers and the icon set are the ones every person here already knows,
which means nobody spends day one relearning where the CSS lives.

---

## The command

Run it in the freshly cloned repository, **after** `bin/kickoff`:

```bash
rails new -d postgresql \
  -m https://raw.githubusercontent.com/lewagon/rails-templates/master/minimal.rb \
  --skip \
  .
```

`--skip` matters: the clone already holds `README.md`, `.github/` and
the method documents. Without it, `rails new` stops on a conflict prompt
for every one of them. With it, what is already there wins.

Then:

```bash
bin/rails db:create db:migrate
bin/dev
```

## What the template decides for you

| Choice | Instead of | Why it is kept |
|---|---|---|
| Sprockets + `sassc-rails` | Propshaft (the Rails 8 default) | The bootcamp stylesheets are SCSS |
| `bootstrap ~> 5.3` + `autoprefixer-rails` | Hand-written CSS | Grid and components on day one |
| `font-awesome-sass ~> 6.1` | Inline SVG | `icon(...)` straight from a view |
| `simple_form` (from GitHub) | `form_with` and manual markup | `f.input` renders a Bootstrap field |
| `lewagon/rails-stylesheets` | Rails' default CSS | The component/token layout of rule 46 |
| Importmap, with Bootstrap and Popper pinned | jsbundling, Yarn, Node | No Node toolchain to keep alive |

🔴 **Sprockets and Propshaft do not coexist.** To go back to Propshaft
you remove the `sprockets-rails` and `sassc-rails` gems **and** restore
`propshaft` in the Gemfile. Half the change leaves an app that does not
boot.

## Add `dotenv-rails` in the same move

The template does not include it, and rule 28 requires it:

```ruby
group :development, :test do
  gem "dotenv-rails"
end
```

Every key then lives in `.env`, which is gitignored — see
[`SECRETS.md`](SECRETS.md).

## Not using it

Legitimate cases: an existing application, a stack that is not Rails, a
deliberate move to Propshaft or Tailwind. Then **write the reason in
`README.md` under "Structural decisions"**, in the same commit. A team
that finds an unexplained bare `rails new` reinstalls the whole thing on
week two, on a hunch.

## Where the enriched version of `minimal` lives

Amorce (`ai-gmented-pm/amorce`, brick `boilerplate`) generates a
`template.rb` derived from the project profile: the same Wagon base,
plus the stack actually practised in class (`ruby_llm`, `cloudinary`,
`neighbor`), a commented option catalogue (devise, pundit, pg_search…)
and a `docs/ACTIVER.md` explaining how to switch each one on.

🔴 **Amorce is authoritative for the `template.rb`.** This document
carries the default and the reasons; it never carries a copy of the
generator. See `KICKOFF.md`, section "Who is authoritative".

Five deliberate departures from Le Wagon's template are documented in
Amorce's generator, the most important being: **the stylesheets are
downloaded before the old ones are deleted**, so a dropped network
connection leaves you with Rails' CSS rather than none at all.
